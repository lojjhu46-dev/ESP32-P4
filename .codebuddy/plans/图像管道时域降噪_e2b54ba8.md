## 产品概述

在板载摄像头 → 图像管道 → AI/回传这条链路里加入**时域降噪（Temporal Denoise, DN）**：利用相邻帧的时间冗余做加权平均压制随机噪声，让夜视/弱光画面显著变干净；并在 LVGL 模拟器 UI 上用按钮在线切换档位（其实就是"夜视低噪"档的进一步强化）。

## 背景与现状

上一轮做的 `Night Lo` 档只降低 sensor 增益，实测噪声仅降 2.5%、信噪比几乎不变（弱光噪声以散粒噪声为主，降增益只是等比缩小信号）。因此改为在**图像管道内做时域降噪**：多帧加权平均可使随机噪声按 √N 下降，这才是真正见效的手段。

## 核心功能

- 图像管道对**板载摄像头帧**做运动自适应时域降噪：静止区域强混合（噪声大幅下降），有运动区域自动减少/停止混合（避免拖影）
- 降噪强度分档：关闭 / 低 / 中 / 高，可运行时切换；默认档可在配置项里设定
- 降噪结果同时作用于 **AI 检测输入**与 **0x05 图像回传**（同一份帧，UI 上能直接看到画面变干净）
- UI 第 4 行新增一个循环档按钮（`DN Off → Low → Mid → High`），点击即切换；结果行回显当前档位
- 关闭档位时行为与改动前完全一致（零额外开销）；图像源切到 PC 送帧、分辨率变化、档位变化或曝光/增益大改时自动重置历史帧，避免残影
- 帧率守卫：在高帧率下若降噪导致摄像头任务吃不消，自动跳过并明确告知（保证链路稳定优先于降噪效果）

## 视觉与交互效果

- 夜视画面噪点（彩色麻点）明显减少，静止画面更干净、不损失清晰度（时域平均不会模糊静止细节）
- 移动物体在最高档位下可能出现轻微拖影/拖尾，档位越低拖影越弱
- UI 上按钮文字随点击在 `DN Off/Low/Mid/High` 之间循环，结果行多出 `dnN` 标识，与板端状态一致

## 技术选型

沿用现有工程栈，不引入任何新依赖：

- 板端：ESP-IDF v5.5.5，C（`main/app_imgpipe.c`），FreeRTOS，PSRAM 帧缓冲
- 链路：JCLINK v1（TCP 192.168.33.2:3333 / USB CDC），0x02 结果 JSON、0x05 图像回传
- UI：LVGL 9.3 的 SDL 模拟器（WSL 编译），同源 `ui_shared.c`
- 验证工具：`pc_host/jc_test.py`（取 raw 帧）、`tools/rgb_stats.py`（noise 指标）

## 实现思路

### 1. 算法：分块运动自适应时域降噪

逐像素运动检测的运算量在这个工程是**明确的性能红线**（历史踩坑：逐像素乘除把 camera 任务 prio 6 占死 → `task_wdt` + faceai 被饿死、0x02 全停）。因此采用**块级运动门控**，把"每像素一次比较"降为"每块一次 SAD"：

- 把帧划分为 `16x16`（或 `8x8`）块；对每块计算 `SAD = Σ|cur - prev|`（在 RGB565 上以打包值近似，或按 2 像素合进 1 个 32bit 来减半循环开销）
- 用 SAD 在**4 级权重查表**里取该块的混合权重 `w`（全静态块 → 强混合；SAD 越大 → 权重越小，超过阈值 → `w=0` 即不混）
- 每像素只做一次 `out = cur + ((prev - cur) * w) >> 5`（移位代替除法，权重表预计算）
- 档位 0/1/2/3 映射为 `{权重档, SAD 阈值}` 两套参数表：档位越高混合越强、判定越宽松

这样每帧的主要开销是 307,200 像素的一次混合（约 5~8 条整数指令）+ 每块一次 SAD，比现有 WB+镜像遍历只多约 1.5~2 倍，且与现有一致地**用整数移位/LUT**，不做逐像素乘除。

### 2. 与现有后处理的合并与顺序

`pipe_postprocess()` 现在是"WB(R/B LUT) + 行内镜像合并成一次遍历"。降噪插入位置与顺序很关键：

- DN 必须在**镜像之前**做（cur 与 prev 都保持传感器原始扫描序，否则会左右错位产生鬼影）
- 因镜像会打乱像素位置，最稳妥的顺序是：在 `app_imgpipe_publish_raw()` 里

1. 读摄像头 mmap 源帧 → `slot = mix(src, prev)`，**同一次循环把混合结果同时写回 prev**（省掉一次 600KB memcpy）
2. 再对 slot 跑现有 `pipe_postprocess()`（WB + 镜像）

- 结果：静止画面噪声降、镜像与白平衡行为不变；AI 与 0x05 消费的都是降噪后的槽内帧，无需改 `app_faceai.cpp` 的取帧逻辑

### 3. 缓冲与失效管理

- 新增 `prev` 缓冲（PSRAM，`stride * height` ≈ `1280 * 480 = 600 KB`），尺寸变化时按 `pipe_copy_into()` 已有的"缓冲失效判断键（cap/pad_w/pad_h）"同款模式释放重分配
- `has_prev` 标志：首帧、分辨率/stride 变化、档位切换、图像源切 PC、曝光/增益/帧率大改 → 置为无效（该帧只填充 prev 不混合），避免亮度突变或换源造成的整屏残影
- 新增 `app_imgpipe_reset_prev()` 公开给 `app_faceai.cpp` 的 cam 命令在改 `exp/gain/fps` 后调用

### 4. 性能守卫（不能牺牲链路稳定性）

- 降噪运行在 camera 任务上下文（prio 6），是全系统最敏感的地方
- 守卫策略：当 `app_camera_get_fps()` 高于配置阈值（默认 25，Kconfig 可调）时**自动跳过降噪**，并在结果帧/日志里标明跳过原因；实现完成后在 50fps 实测，若稳定再决定是否上调阈值
- 统计口径：新增 `dn_ms`（降噪耗时）随结果帧回传，便于观察成本；`dn=0` 时直接 return，保证零开销
- 若实测高帧率仍不稳，则回退方案是把 DN 只在低帧率档生效并写进文档（明确告知用户）

### 5. 控制面

- 板端：`{"cmd":"cam","dn":0..3}` 设置、缺省即查询；结果帧新增 `"dn"`（当前档位）与 `"dn_ms"`
- UI：第 4 行由 4 个按钮扩成 5 个（与第 3 行 5 个按钮宽度一致，已有先例），新增循环档按钮，点击发 `{"cmd":"cam","dn":N}` 并按 ack 更新按钮文字；结果行追加 `dnN`

## 关键代码结构（接口级）

```c
/* app_imgpipe.h —— 时域降噪 */
/*
 * 时域降噪档位：0=关，1=低，2=中，3=高。
 * 仅对摄像头 raw 路径生效（PC 送帧时序不连续，无意义）。
 * 内部做"分块运动自适应"混合：静止块强混合、运动块减弱或跳过，避免拖影。

/* 统计扩展 */
typedef struct {
    /* ... 原有字段 ... */
    uint32_t dn_skip;     /* 因高帧率守卫被跳过的帧数 */
} app_imgpipe_stats_t;
```

## 实施注意

- **必须遵守的既有约束**：`pdMS_TO_TICKS(2)=0`（小延时用 `vTaskDelay(1)`）；逐像素处理只用移位/LUT；不调用驱动侧 WB（`app_camera_set_wb()` 会阻塞卡死 faceai）；不改 `main/idf_component.yml` 的 override_path 结构
- **顺序不可颠倒**：先混合后镜像；prev 始终保存"未镜像"内容，否则会出现左右错位鬼影
- **失效时机**要一次性列全（首帧/尺寸/档位/换源/曝光增益），否则残影会被误判成算法问题
- **烧录**：`chcp 65001` + `Set-Item Env:PYTHONIOENCODING utf-8` 后 `idf.py -p COM4 flash`（否则 esptool 进度字符 ϵ 触发 GBK 编码错误静默失败）
- **性能验收以实测为准**：若 50fps 下开启降噪出现 `task_wdt` 或 camera 帧率下降，立即启用/收紧帧率守卫并把结论写进文档，不要为了效果牺牲链路稳定
- **量化对比要同场景短间隔**（上一轮踩过：间隔 30 秒场景变了导致对比无效），用 `noise(grad)` 判定噪声下降，同时用高阶梯度（边缘能量）确认静止细节没被削弱
