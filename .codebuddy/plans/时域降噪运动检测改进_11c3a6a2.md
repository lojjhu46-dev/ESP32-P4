## 需求描述

实测反馈：静止画面下，帧率越低噪点越少、画面越清晰；但画面中出现运动物体时，越低帧率的残影与画面滞留越严重（50fps 几乎无残影，25fps 起明显）。经诊断，残影由两部分叠加：时域降噪把历史帧影像带进画面（算法拖影），以及长曝光的物理运动模糊。

本轮决定：**改进降噪的运动检测** —— 判定网格更细、判据对小范围运动更敏感、运动区域彻底不参与多帧混合，从根本上消除算法拖影；帧率与曝光策略保持不变（物理运动模糊不做处理）。同时要求界面实时显示"当前画面运动程度"，便于判断场景动静与档位选择。

## 核心功能

- 运动判定细化：降噪分块由 16x16 缩小为 8x8，判定更细，小目标运动不再被大块的"平均值"稀释
- 判据升级：由"块内采样点差值均值"改为"块内最大差值"，只要块内存在明显变化即判定为运动
- 门限收紧并按新判据重新标定：运动区域混合权重直接归零（完全保留当前帧内容），静止区域维持原有降噪力度
- 历史一致性处理：判定为运动的区域在跳过混合的同时，把当前帧内容同步刷新到历史缓存，避免旧影像滞留在历史里、运动停止后"闪回"
- 实时运动程度反馈：结果帧回传运动块占比，界面结果行显示 `mvNN%`（静置接近 0%，挥手/移动时明显升高）
- 既有控制方式不变：降噪开关与低/中/高三档、帧率档位、曝光与增益滑块等均保持原样

## 视觉效果

- 降噪开启时，静止场景依旧干净（噪点压制保持此前水平）；画面中出现运动物体时不再留下半透明拖影，运动区域直接呈现当前帧（物理运动模糊仍在，属曝光时间决定的固有限制）
- 界面结果行形如 `faces 0 - 2.6 fps 17 ms lib 4 cam10fps dn3 mv12%`，末尾运动占比随画面动静实时变化
- 档位越高，运动判定越保守、静止区域越干净；运动占比越高说明画面越"动"、降噪可发挥的空间越小

## 实现思路

### 1. 运动判据改造（`pipe_dn_apply`，核心改动）

- 常量：`DN_BLOCK` 16 改为 **8**（4800 块，判定更细）；`DN_SAD_STEP` 4 改为 **2**（每块仍取 4x4=16 个采样点，检测成本约 4 倍但绝对值很小，约 1ms）
- 每块同时计算两个量：**均值差**（沿用现有逻辑，继续作为 `dn_sad` 统计，便于与旧标定数据对比）与**最大差 `mmax`**（新判据，G 通道 6bit，0..63）
- 权重决策改用 `mmax`：`mmax ≥ mmax_hi` 时权重归零（跳过混合）；`mmax_lo..mmax_hi` 之间线性衰减；否则全混。权重计算仍是每块一次除法（可接受），像素混合仍是移位实现
- **跳过块刷新历史（新增）**：跳过混合时把该块当前帧内容写入 prev。否则旧残影会"冻结"在历史里，运动停止后（差异落到阈值内）被混回画面造成闪回
- 门限起始值（max 判据数值约为旧均值的 2.5 倍量级，最终以实测标定为准）：低 {14,28}、中 {16,32}、高 {18,38}；`s_dn_tab` 字段更名为 `mmax_lo / mmax_hi`，注释同步更新
- 顺带修正 `pipe_dn_apply` 中一处过时注释（外层仍写着"整包 16bit 线性插值"，实际已是分量混合）

### 2. 统计与数据透传

- `app_imgpipe_stats_t` 新增：`dn_mmax`（块内最大差的全帧平均，0..63，调参用）、`dn_motion`（运动块占比 0..100，定义为"权重被减弱或完全跳过"的块占比）
- `app_imgpipe.c` 函数末尾统计写入；保留 `dn_sad / dn_blocks / dn_ms / dn_skip` 语义不变（`dn_blocks` 总数随块变化为 4800）
- `app_faceai.cpp`：状态缓存新增 `s_cam_dn_mv / s_cam_dn_mmax`，结果帧在降噪开启时增加 `dn_mv`（百分比整数）与 `dn_mmax` 字段（字段少、每帧开销可忽略）
- `ui_shared.c`：解析 `dn_mv`（默认 -1），降噪开启时在结果行末尾追加 `mvNN%`；不新增控件、不占按钮行、不改图像区尺寸

### 3. 门限标定方法（改完必须实测标定）

1. 静止场景基线：`dn=3`、10fps，观察 `dn_mv` 应接近 0（目标不超过 5%）、`dn_blk` 接近 4800（几乎全混）、`noise2` 相比 `dn=0` 仍降约 40%；若静止基线过高则上调 `mmax_lo/hi`
2. 运动场景：请用户挥手/移动物体（或转动板子），观察 `dn_mv` 明显升高、运动区域块被跳过、抓帧看运动物体无半透明拖影；若小运动漏检则下调 `mmax_hi`
3. 迭代：两者冲突时优先保证"静止安静、运动不拖影"，门限以实测分布中值为准

### 4. 性能与稳定性

- 检测采样 4800x16=76800 次（原 19200 次，增加约 1ms）；跳过块的"刷新历史"是每行字节拷贝，比混合更便宜（跳过越多总耗时越低）
- 预期 `dn_ms` 不超过约 38ms（当前全混 34ms）；逐像素仅整数与移位，禁止除法/浮点；块级除法每块一次可接受
- 25fps 下运动区域大量跳过后耗时自然下降，配合更严门限，此前的明显拖影应显著改善

## 实施注意事项

- 混合必须按 R/G/B 分量分别进行（RGB565 整包插值会跨分量借位，此前曾导致噪声反涨 2.6 倍并出彩色伪影）
- 降噪必须在镜像之前调用（prev 保存未镜像内容，否则左右错位出鬼影）
- 本次不改 Kconfig、不需 `idf.py reconfigure`；板端 `idf.py build`、模拟器 WSL 下 `cmake --build build -j 8`
- 烧录需先 `chcp 65001` 与设置 `PYTHONIOENCODING=utf-8`（否则 esptool 进度字符触发 GBK 编码错误、静默失败）
- 对照测试必须同场景短间隔（此前踩过间隔过长场景变化导致对比无效）；抓 raw 前先发 `{"cmd":"stream","value":"on","fps":5,"fmt":"raw"}`
- 日志节制：调参数据走结果帧字段与按需查询，不要按帧打日志
- 文档中明确：物理运动模糊由曝光时间与帧周期决定，软件无法消除；低帧率更适合静态/慢速场景

#define DN_BLOCK     8        /* 16 改为 8：块太大时局部小运动被均值稀释 */
#define DN_SAD_STEP  2        /* 采样步长，8x8 块取 4x4=16 点 */

static const struct { int wq; int mmax_lo; int mmax_hi; } s_dn_tab[4] = {
    {   0,   0,   0 },        /* 0 = 关 */

    { 236,  18,  38 },        /* 3 = 高 */

/* 决策：mmax 达到 mmax_hi 的块跳过混合并刷新 prev；中间值线性衰减权重 */

uint32_t dn_mmax;    /* 块内最大差的全帧平均 0..63（调参用） */
