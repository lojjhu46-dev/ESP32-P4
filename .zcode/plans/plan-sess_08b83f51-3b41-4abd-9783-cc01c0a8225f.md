# 夜视效果修复：app 层恢复 ISP 硬件 Gamma 提亮 + BF 降噪（自适应）

## 根因（探索已确认）

关闭 IPA 控制器时，它每帧写入 ISP 硬件的**低光增强**整体消失（esp_video_isp_pipeline.c 随
Kconfig 一起不参与编译）：
1. **Gamma 暗部提亮**（sc2336_default.json aen 段 gamma_param=0.688）——ISP gamma 模块现在
   关闭、线性输出，**画面发暗发灰的主因**；
2. **BF 拜耳域降噪**（adn 段：随增益 level 3→7 + 3x3 矩阵 {2,4,2;4,5,4;2,4,2}）——BF 模块
   关闭，高增益噪点更刺眼；
3. sharpen/demosaic/对比度随增益自适应（次要，本次不恢复）。

这些模块可经 `/dev/video20` 用 `V4L2_CID_USER_ESP_ISP_GAMMA(0x009810E1)` /
`_BF(0x009810E2)` 直接控制（explore 已确认 payload 结构与硬约束：gamma 16 点、x 严格递增、
相邻差为 2 的幂、末点 x=255、y<256；BF level∈[2,20]、矩阵[0,15]；ISP streaming 中 set 即
live 生效）。硬件 WB 已有同款通道（CAM_MREQ_WB 范本）。

用户决策：**自适应自动**（亮时无影响、暗时自动加强，Night 预设自动包含）；**帧率保持 10fps
下限**（不动 fps/exp_max 公式）。

## 改动内容

### 1. app_camera：信箱扩展 GAMMA / BF 请求（走 /dev/video20）
- 新增 `CAM_MREQ_GAMMA`（payload：gamma 千分比，1000=不提亮，0=禁用模块）与
  `CAM_MREQ_BF`（payload：level，0=禁用）。
- `camera_mailbox_run()` 执行：GAMMA——用固定 16 点 x 序列
  `{0,1,2,4,8,16,32,64,128,192,224,240,248,252,254,255}`（相邻差全为 2 的幂、末点 255，满足
  驱动校验），`y = 255*(x/255)^g`（powf，一次浮点在 camera 任务低频执行无碍），y 末点强制
  255、严格递增（max 钳位）；BF——enable + level + IPA 同款矩阵 {2,4,2;4,5,4;2,4,2}。
- API：`app_camera_post_gamma(int gamma_permille)` / `app_camera_post_bf(int level)`
  （level 0 = disable）；复用 `s_isp.fd` 与 `app_camera_wb_available()` 判可用。
- set 失败打日志（限流）。

### 2. app_camauto：夜视增强自适应状态机
- 新状态 `enh_on`（`CONFIG_APP_CAM_NIGHT_ENH` 默认 y）+ 当前生效 gamma_permille/bf_level
  （避免重复下发）。
- **gamma 按亮度自适应**（慢节流 2s + luma EMA(1/4) + 迟滞，防与 AE 测量耦合振荡）：
  EMA luma ≥70 → 1000（不提亮）；≤45 → `CONFIG_APP_CAM_GAMMA_MIN`（默认 650）；中间线性
  过渡；变化 ≥5% 才下发。
- **BF 按增益自适应**（对齐 IPA 表）：gain<8 → level 3；≥8 → 4；≥48 → 5；≥120 → 6。
- 门控调整：现在 `camauto_tick` 在 `!ae_on && !awb_on` 时直接返回——改为
  `!(ae_on||awb_on||enh_on)`；即手动 Night 档（AE off）也能自适应。
- 关闭总开关 → gamma 下发 0（disable）+ BF 0（disable）。
- 手动命令：`{"cmd":"cam","gamma_en":true|false,"gamma":0.65,"bf_level":N}`——手动设置时
  自适应让位（同 AE/AWB 手动优先规则）；`enh` 总开关命令 `{"cmd":"cam","enh":bool}`。
- 结果帧 ack msg 追加 `gamma=x bf=N`；结果 JSON 增加字段 `gamma`（千分比）便于调试。

### 3. faceai 接入
- `cam` 命令解析新增 enh/gamma_en/gamma/bf_level；
- cam_state_tick 不需要动（增强状态由引擎内部管理，结果帧字段从引擎 getter 取）。

### 4. Kconfig（main/Kconfig.projbuild）
- `APP_CAM_NIGHT_ENH`（bool，默认 y，depends APP_ENABLE_CAMERA）：自适应夜视增强总开关；
- `APP_CAM_GAMMA_MIN`（int 千分比，默认 650，range 300..1000）：最暗时的 gamma 参数。

### 5. 文档
- HANDOVER.md 第十一节追加"夜视增强（2026-10-01 第二轮）"：根因（IPA gamma/BF 丢失对照
  表）、通道用法、自适应策略、实测数据；更新文档头部摘要。

## 不做的事（边界）
- 不动帧率下限与 `1000*50/fps-6` 公式（fps≥10 时公式恒正确）。
- 不恢复 sharpen/demosaic/对比度自适应（次要，先看 gamma+BF 效果）。
- 不加 UI 按钮（自适应自动 + Night 预设自动包含；命令可调）。

## 验证（真机，COM4 + 模拟器 + jc_test）
1. 编译烧录（惯例 chcp 65001 + PYTHONIOENCODING）。
2. **暗场验收**：遮光/关灯 → AE 推高 exp/gain 后触发增强，结果帧 `gamma` 降到 ≤650、
   `bf` level≥4；对比 gamma on/off 各抓一张 0x05（`jc_test.py img` + `tools/rgb_stats.py`）：
   暗部（阴影区）均值提升、观感对比截图存 `docs/img/night_gamma_20261001.png`。
3. **亮场无回归**：正常光照 gamma≈1000、BF level 3，画面与现在无可感知差异（截图对比）。
4. **稳定性**：观察 luma/gamma 序列无振荡（自适应迟滞生效）；10 分钟无 WDT/重启、0x02 连续。
5. UI 截图（模拟器）留档。

## 风险与对策
- gamma↔AE 测量耦合回路振荡 → 慢节流(2s)+EMA+宽迟滞（45/70）压制，实测观察序列；
  仍振荡则改为按 AE 增益利用率（而非 luma）驱动 gamma。
- BF stop/start 在 streaming 中由 esp_video live 重配（IPA 时代每帧如此），风险低；
  若 BF set 报错则日志限流并保持上一档。
- esp_video 不钳位、IDF 驱动校验严格（gamma 点约束）→ 曲线构造函数内保证合法，
  set 失败留日志便于定位。
